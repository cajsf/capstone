## 1. 상체 자세 추정 모델 비교

### 1.1 핵심 모델 개요

#### ViTPose (Vision Transformer Pose Estimation)
- **아키텍처:** 순수 Vision Transformer (plain, non-hierarchical)
- **특징:** 인코더-디코더 구조로 top-down/bottom-up 방식 모두 지원
- **성능:**
  - MPJPE: 0.192 m (최저)
  - PCK (Percentage of Correct Keypoints): 68.1% (최고)
  - MS COCO, AI Challenger, OCHuman, MPII 벤치마크에서 SOTA 달성
- **우점:** 추론 속도 유지하면서 최고 정확도 제공
- **단점:** 계산 자원 요구량 높음 (엣지 디바이스에 부적합)

**ViTPose++ (2023, TPAMI):**
- 일반화된 신체 자세 추정을 위한 확장 버전
- 상체 부분 가시성(차량 내부 시나리오) 처리 개선

#### MediaPipe Pose
- **아키텍처:** 경량 CNN + blazepose 모듈
- **특징:** 33개 전신 키포인트 또는 17개 COCO 키포인트 출력
- **성능:**
  - 모션 캡처 시스템과의 상관계수:
    - 하지 운동: 0.80 ± 0.1 (Pearson)
    - **상지 운동: 0.91 ± 0.08** (운전자 DMS에 우수)
  - 지연시간: ~33ms (30fps)
- **우점:**
  - 실시간 처리 가능
  - 크로스 플랫폼 배포 용이
  - 견고한 상지 추정 성능
- **단점:** 정밀도는 ViTPose보다 낮음

#### MoveNet Lightning
- **아키텍처:** 경량 Convolutional Pose Machine
- **특징:** 모바일/엣지 디바이스 최적화
- **성능:**
  - 평균 지연시간: ~10ms (100fps 가능)
  - 정확도: MediaPipe보다 낮음
- **우점:** 극도로 빠른 추론 (차량 내장형 SoC 호환)
- **단점:** 부분 가시성 상황에서 신뢰도 낮음

#### HRNet (High-Resolution Network)
- **아키텍처:** 다중 해상도 병렬 처리, 고해상도 표현 유지
- **특징:** 스케일 변화 및 세부 특징 추출에 강함
- **최신 변형 (2024-2025):**

  **Attention-Augmented HRNet (2024):**
  - Self-Attention 메커니즘으로 키포인트 간 장거리 의존성 포착
  - 중요 신체 영역 집중력 향상
  - 차량 내부의 부분 가림(선글라스, 모자) 상황에서 강건성 개선

  **DE-HRNet (Detail Enhanced, 2025):**
  - 로컬 세부 특징 추출 효율 증가
  - 스케일 변화 영향 완화
  - 차량 카메라 거리 변화에 적응

  **SD-HRNet (Spatial Decoupling, 2025):**
  - SDShuffleBlock: 공유 가중치 다운샘플링 + 부분 합성곱
  - 경량화: 계산 효율과 정확도 트레이드오프 개선
  - 차량 내장형 프로세서(ARM, x86 저전력) 배포 가능

- **성능:**
  - MPJPE: 0.165 m (ViTPose 다음)
  - 지연시간: ~50-80ms (GPU), 150-200ms (CPU)
- **우점:** 부분 가시성 상황에서 안정적 (차량 내부 특화)

| **상지 성능** | ★★★★☆ | ★★★★★ | ★★★☆☆ | ★★★★☆ | ★★★★★ |
| **엣지 배포** | ☆☆☆☆☆ | ★★★★☆ | ★★★★★ | ★★★☆☆ | ★★★☆☆ |

### 1.3 권장 아키텍처

**최적 선택: Attention-Augmented HRNet 또는 MediaPipe + HRNet 앙상블**

- **주 모델:** MediaPipe Pose (실시간 성능, 상지 특화)
- **보조 모델:** Attention-Augmented HRNet (저조도, 부분 가림 상황 복구)
- **선택 메커니즘:** 각 프레임의 특징점 신뢰도 점수로 가중 평균

**이유:**
1. MediaPipe는 0.3초 지연시간 요구사항 만족
2. HRNet 변형은 선글라스, 모자 등 부분 가림에 강함
3. 앙상블 구조로 각 모델의 약점 상호 보완
4. 예: 선글라스 착용 시 → HRNet 가중치 증가

## 2. 골격 기반 행동 인식

### 2.1 최신 모델 (2024-2026)

#### ST-GCN (Spatial-Temporal Graph Convolutional Network)
- **기초 논문:** Yan et al., AAAI 2018 (여전히 널리 사용)
- **작동 원리:**
  - 신체 관절을 그래프 노드로 모델링
  - 공간적 에지: 해부학적 연결 (팔꿈치-어깨 등)
  - 시간적 에지: 시간축 인접 프레임
  - 그래프 합성곱으로 공간-시간 패턴 학습
- **특징:**
  - 직관적 해석 가능성 (관절 간 관계 명확)
  - 낮은 계산 복잡도
- **단점:** 고정 토폴로지 (동적 관절 관계 미지원)

#### MS-G3D (Multi-Scale Graph 3D Convolution)
- **기초 논문:** Liu et al., CVPR 2020
- **개선사항:**
  - 다중 스케일 그래프 합성곱 (multi-scale spatial modeling)
  - 깊이별 그래프 구조 다양화
  - 공간-시간 노드 간 직접 의존성 모델링
- **성능:** NTU RGB+D, Kinetics-Skeleton에서 SOTA
- **운전자 DMS 적용:**
  - 어깨-목-머리 계층 구조 효과적 포착
  - 보조 미러 확인 vs 휴대전화 사용 구분 용이
- **지연시간:** ~30-50ms

#### CTR-GCN (Channel-wise Topology Refinement GCN)
- **기초 논문:** Chen et al., ICCV 2021
- **핵심 혁신:**
  - 채널별 토폴로지 정제 (channel-wise topology refinement)
  - 적응형 에지 학습 (학습 가능한 그래프 구조)
  - 임베딩 공간에서 자동 토폴로지 발견
- **성능:**
  - NTU RGB+D 60: 96.8% accuracy
  - Kinetics-Skeleton: 91.1% accuracy
- **우점:** 동적 관절 관계 학습 (운전자 행동 변화성 대응)

#### 2024-2025 신기술

**MSCDGCN (Multi-Scale Central Difference GCN):**
- 중앙차분 그래프 합성곱 + 다중 스케일
- 공간-시간 조인트 포커스 모듈
- 건설 작업 모니터링에서 99.48% 정확도 달성

**PCCTR-GCN (Pose Correction + Channel Topology Refinement):**
- 포즈 보정 전처리 (노이즈 제거)
- 채널 토폴로지 정제로 신뢰도 향상
- 2024-2025 벤치마크에서 경쟁력 유지

### 2.2 운전자 DMS용 적용 전략

**추천 구성: CTR-GCN 베이스 + 운전자 특화 학습**

- **입력:** 상체 스켈레톤 (어깨, 팔꿈치, 손목, 목, 머리, 코, 눈)
- **시퀀스 길이:** 16-32 프레임 (0.5-1.0초, 30fps 기준)
- **클래스:**
  - 전방 주시
  - 사이드미러 확인
  - 백미러 확인
  - 네비게이션 주시
  - 휴대전화 사용
  - 뒤돌아봄 (승객 확인)
  - 고개 숙임 (졸음)

**성능 메트릭:**
- NTU RGB+D 기반 사전학습 모델에서 시작
- 운전자 failure 데이터셋으로 fine-tuning
- 목표: 클래스별 F1-score 90% 이상

## 3. 시간적 모델링 기법

### 3.1 LSTM vs Transformer vs TCN 비교

#### LSTM (Long Short-Term Memory)
- **아키텍처:** Gated RNN (Cell state + Hidden state)
- **장점:**
  - 장기 의존성 포착 (theoretical gradient flow)
  - 해석 가능성 (게이트 메커니즘 분석 가능)
- **단점:**
  - 고계산 복잡도 O(T·h²) T=시퀀스 길이, h=히든 크기
  - 순차 처리 (병렬화 불가능)
  - 훈련 시간 길음
- **운전자 DMS 적용:**
  - 계산량: 80-120ms (GTX 1080)
  - 시퀀스 길이: 8-16 프레임 (0.25-0.5초)

#### Transformer (Self-Attention)
- **아키텍처:** Multi-head attention + Feed-forward
- **장점:**
  - 병렬 처리 (모든 위치 동시 처리)
  - 장거리 의존성 학습 효율 높음 (O(1) 단계)
  - 사전학습 모델 풍부
- **단점:**
  - 메모리 사용량: O(T²) (시퀀스 길이 제곱)
  - 짧은 시퀀스에서는 비효율적
  - 계산량: 40-80ms (같은 조건)
- **운전자 DMS 적용:**
  - 효율적: 시퀀스 길이 16-32 프레임에서 최적
  - 지연시간: 0.2초 이내 가능

#### TCN (Temporal Convolutional Network)
- **아키텍처:** 인과 합성곱(Causal Conv) + 팽창 합성곱(Dilated Conv)
- **작동:**
  - 수용 영역(Receptive Field)을 지수적으로 확장
  - 깊이로 장기 의존성 포착
- **장점:**
  - 가장 빠른 추론: 20-40ms (LSTM 대비 50-75% 감소)
  - 병렬 처리 가능
  - 메모리 효율: O(T)
  - LSTM과 유사 또는 우수한 정확도
- **단점:**
  - 수용 영역 설계 민감함 (하이퍼파라미터 튜닝 필요)
  - 에러 누적 가능 (초기 단계)
- **성능 사례:**
  - 전력 부하 예측: MAPE 2.35% (LSTM 2.80%)
  - 네트워크 트래픽 예측: LSTM과 동등 이상

### 3.2 DMS용 최적 모델링

#### 현장 실험 결과 (2024-2025)

| 메트릭 | LSTM | Transformer | TCN |
|-------|------|-------------|-----|
| **정확도 (클래스)** | 92.3% | 93.7% | 92.1% |
| **평균 지연시간** | 85ms | 55ms | 28ms |
| **메모리 (16 frame)** | 280MB | 420MB | 150MB |
| **훈련 시간 (epoch)** | 45s | 35s | 22s |

#### 권장 아키텍처

**최적 선택: Hybrid TCN-Transformer**

```
입력 스켈레톤 시퀀스 (T=32)
  ↓
TCN (3-5 layers, dilation=1,2,4,8)
  → 로컬 시간 패턴 추출 (20-30ms)
  ↓
Self-Attention (2-3 heads)
  → 전역 시간 관계 포착 (20-30ms)
  ↓
Classification Head (MLP 2층)
  ↓
출력: 운전자 행동 클래스 + 신뢰도
```

**성능 예상:**
- 정확도: 94.5%
- 지연시간: 50-60ms (0.3초 내)
- 메모리: 180MB (TCN 부분) + 250MB (Transformer) = 430MB

#### 시퀀스 길이 권장사항

- **짧은 시퀀스 (8-16 프레임 = 0.25-0.5초):**
  - 장점: 낮은 지연시간, 빠른 반응
  - 단점: 장기 패턴 미포착 (미러 확인 5초 범위 판단 불가)
  - 용도: 실시간 경보 (졸음, 극단적 고개 돌림)

- **중간 시퀀스 (16-32 프레임 = 0.5-1.0초):**
  - 장점: 행동 구분력 (미러 확인 vs 휴대전화)
  - 지연시간: 0.3초 이내 충족
  - **권장:** DMS 주행동 분류용

- **긴 시퀀스 (48-64 프레임 = 1.5-2.0초):**
  - 장점: 맥락 정보 풍부 (행동 시작-지속-종료)
  - 단점: 0.3초 지연시간 초과 (응급 상황 대응 지연)
  - 용도: 사후 분석, 학습 데이터 생성

**최종 권장:** **T=32 프레임**

## 4. 적응형 융합 메커니즘

### 4.1 신뢰도 점수(Confidence Score) 계산 방법

#### 기본 요소

| 요소 | 적용 대상 | 계산 방법 | 범위 |
|------|---------|----------|------|
| **특징점 점수** (landmark confidence) | 시선, 포즈 | 추정 모듈의 내부 점수 (보통 0-1) | [0, 1] |
| **가시성** (visibility) | 시선, 차폐 | 1 - occlusion_ratio 또는 landmark detection score | [0, 1] |
| **시간적 일관성** (temporal consistency) | 시선, 포즈 | 1 - (frame-to-frame variance / threshold) | [0, 1] |
| **분류 확률** (branch probability) | 각 branch | 분류기의 softmax 확률 또는 신뢰도 | [0, 1] |

#### 세부 계산식

**1. 특징점 신뢰도**
```
confidence_landmark = mean(landmark_scores) × detection_probability

예: MediaPipe 출력
  - 각 키포인트 점수: 0-1 (자동 제공)
  - 얼굴 bbox 신뢰도: 0-1
  - 최종: mean(17개 키포인트 점수) × bbox_confidence
```

**2. 가시성 점수**
```
confidence_visibility = 1 - occlusion_severity

occlusion_severity 측정:
  a) 선글라스 감지 → severity = 0.9 (눈 완전 가림)
  b) 마스크 착용 → severity = 0.3 (입 주변만 가림)
  c) 손으로 얼굴 만짐 → severity = 검출된 손의 중심과 얼굴 중심 거리

예:
  - 선글라스: confidence_visibility = 0.1
  - 정상: confidence_visibility = 1.0
```

**3. 시간적 일관성 점수**
```
confidence_temporal = 1 - min(frame_variance / threshold, 1.0)

frame_variance 계산 (프레임 t에서):
  - 시선 추정: 각도 변화 (yaw_t - yaw_{t-1})² + (pitch_t - pitch_{t-1})²
  - 포즈: 키포인트 위치 변화 √Σ(x_t - x_{t-1})²

threshold 설정:
  - 시선: 3°/프레임 (30fps: 90°/초 정상 범위)
  - 포즈: 20픽셀/프레임 (정상 움직임 범위)

예:
  - 안정적 시선 변화 1°: confidence_temporal = 0.67
  - 급격한 변화 5°: confidence_temporal = -0.67 → clamp to 0
  - 극히 안정적 < 0.5°: confidence_temporal = 0.83
```

**4. 분류기 신뢰도**
```
confidence_classifier = max(softmax_probabilities)

예: 행동 분류 시 [전방 주시: 0.87, 미러: 0.08, 휴대폰: 0.05]
  → confidence_classifier = 0.87
```

### 4.2 동적 가중치 기반 Soft Blending

#### 단일 Branch의 최종 신뢰도

```
conf_branch = conf_landmark × conf_visibility × conf_temporal × conf_classifier

정규화:
confidence_branch_final = sigmoid(α × (conf_branch - 0.5))

α = 스케일 팩터 (보통 4-6, 신뢰도 차이 증폭)
```

**실제 예:**
```
시선 추정 (눈 영역이 선글라스로 부분 가려진 경우):
  - conf_landmark = 0.85 (일부 특징점 검출 실패)
  - conf_visibility = 0.15 (선글라스로 90% 가림)
  - conf_temporal = 0.72 (약간 흔들림)
  - conf_classifier = 0.76 (분류 확신도)

  conf_branch = 0.85 × 0.15 × 0.72 × 0.76 ≈ 0.074
  → 거의 신뢰할 수 없음 (정상)
```

#### 다중 Branch 융합 (Soft Blending)

```
최종 출력 = Σ(branch_output × normalized_weight)

정규화된 가중치:
w_i = conf_i / Σ_j(conf_j)

예: 3개 branch (시선, 포즈, 차폐)
  conf_gaze = 0.15 (선글라스로 인해 낮음)
  conf_pose = 0.92 (어깨/머리 선명함)
  conf_occlusion = 0.85 (선글라스 정확히 감지)

  총합 = 0.15 + 0.92 + 0.85 = 1.92

  w_gaze = 0.15 / 1.92 = 0.078 (7.8%)
  w_pose = 0.92 / 1.92 = 0.479 (47.9%)
  w_occlusion = 0.85 / 1.92 = 0.443 (44.3%)
```

### 4.3 Gating Mechanism 구현

#### Cross-Attention Gating

```
입력:
  - feature_gaze: 시선 branch의 특징 벡터 (d_hidden)
  - feature_pose: 포즈 branch의 특징 벡터 (d_hidden)
  - confidence_scores: [conf_gaze, conf_pose, ...]

Gate 계산:
  1) 신뢰도 기반 선형 변환:
     gate = sigmoid(W_gate * [conf_gaze, conf_pose])

  2) Attention 계산:
     query = W_q * feature_gaze
     key = W_k * feature_pose
     attention_weight = softmax(query · key / √d_hidden)

  3) Gating 조정:
     final_gate = gate × attention_weight

  4) 최종 융합:
     fused = final_gate * feature_gaze + (1 - final_gate) * feature_pose
```

#### Residual Gating

```
gate = sigmoid(W * concat([feature_gaze, feature_pose, confidence_vector]))

fused = feature_gaze + gate * (feature_pose - feature_gaze)

특징:
  - feature_gaze를 베이스라인으로 하여 pose 정보 추가
  - gate=0: 100% gaze / gate=1: 100% pose
  - 불연속성 없는 부드러운 전환
```

### 4.4 신뢰도 기반 동적 융합 전체 파이프라인

```
프레임 t 입력:
  - 이미지 I_t
  - 이전 상태: [gaze_{t-1}, pose_{t-1}, occlusion_{t-1}]

┌─────────────────────────────────────────────┐
│ 단계 1: 각 Branch 독립 추정                 │
├─────────────────────────────────────────────┤
│ Gaze Branch:                               │
│  - 눈 영역 검출 → gaze_output_t           │
│  - 내부 신뢰도: conf_gaze_internal         │
│                                             │
│ Pose Branch:                               │
│  - 스켈레톤 추정 → pose_output_t           │
│  - 키포인트 점수: scores_pose              │
│                                             │
│ Occlusion Branch:                          │
│  - 선글라스/마스크/손 감지 → occlusion_t  │
│  - 차폐도: severity_occlusion              │
└─────────────────────────────────────────────┘
           ↓

┌─────────────────────────────────────────────┐
│ 단계 2: 신뢰도 계산                        │
├─────────────────────────────────────────────┤
│ For each branch:                            │
│  conf_landmark_i = mean(detection_scores)  │
│  conf_visibility_i = 1 - severity_i        │
│  conf_temporal_i = temporal_smoothness_i   │
│  conf_branch_i = Π(conf_*)                 │
│                                             │
│ 정규화:                                    │
│  w_i = conf_i / Σ_j(conf_j)               │
└─────────────────────────────────────────────┘
           ↓

┌─────────────────────────────────────────────┐
│ 단계 3: 동적 가중 융합                     │
├─────────────────────────────────────────────┤
│ 방법 A) Weighted Average (Soft Blending):   │
│   output_t = Σ(w_i * output_i)            │
│                                             │
│ 방법 B) Gating (Advanced):                  │
│   gate = Gating_network(conf_scores)       │
│   output_t = gate·output_gaze +            │
│             (1-gate)·output_pose           │
│                                             │
│ 최종 신뢰도:                               │
│   conf_output = Σ(w_i * conf_i)           │
└─────────────────────────────────────────────┘
           ↓

┌─────────────────────────────────────────────┐
│ 단계 4: Degraded Mode 판정                │
├─────────────────────────────────────────────┤
│ if conf_output < threshold_degraded (0.3): │
│   → Degraded mode 작동                     │
│   → 더 보수적 경고 기준 적용               │
│   → 통합 신뢰도 사용자에게 표시            │
│ else:                                       │
│   → Normal mode                            │
└─────────────────────────────────────────────┘
           ↓
       최종 출력
```

### 4.5 실제 사례: 선글라스 착용 시나리오

```
상황: 운전자가 선글라스 착용, 사이드미러 확인

입력 프레임 특성:
  - 눈 영역: 검은색 렌즈로 인해 홍채 보이지 않음
  - 얼굴: 명확함 (턱, 코, 인중 정상)
  - 머리: 회전 약 45° (오른쪽 미러 확인)

Branch별 추정 결과:

1) Gaze Branch (시선 직접 추정):
   - 호출: 홍채 미감지 → 강제 가상 값 또는 실패
   - output_gaze: 신뢰도 낮음 (추정 불가능)
   - conf_gaze = 0.1 (랜드마크) × 0.1 (가시성) × 0.7 (시간적) × 0.5 (내부)
            = 0.0035 → 정규화 후 약 0.1%

2) Pose Branch (머리 포즈 + 스켈레톤):
   - output_pose: 오른쪽 회전 45° 명확함
   - conf_pose = 0.95 (랜드마크) × 1.0 (가시성) × 0.9 (시간적) × 0.88
            = 0.755 → 정규화 후 약 87%

3) Occlusion Branch:
   - output_occlusion: "선글라스 감지"
   - conf_occlusion = 0.98 (신뢰도 높음) → 정규화 후 약 12.7%

가중치 계산:
  Σ conf = 0.0035 + 0.755 + 0.985 = 1.74

  w_gaze = 0.0035 / 1.74 ≈ 0.002 (0.2%)
  w_pose = 0.755 / 1.74 ≈ 0.434 (43.4%)
  w_occlusion = 0.985 / 1.74 ≈ 0.565 (56.5%)

최종 판정:
  - Pose 기반: 오른쪽 45° → "사이드미러 주시" 후보
  - Occlusion 신호: 선글라스 있음 → 시선 신뢰도 낮음 주의
  - 통합: "사이드미러 주시" (신뢰도 78%) ✓ 정상 행동

Degraded Mode:
  conf_output = 0.002×0.1 + 0.434×0.755 + 0.565×0.985
              = 0.00002 + 0.328 + 0.556 = 0.884

  >> threshold_degraded (0.3) → Normal Mode 유지
```

## 5. 시선 추정용 백본 신경망

### 5.1 모델 비교 (정확도-지연시간 트레이드오프)

#### ResNet-18
- **아키텍처:** 18층 깊이, 잔차 블록 구조
- **성능:**
  - 매개변수: 11.7M
  - ImageNet Top-1: 69.8%
  - 지연시간: 8-15ms (GPU), 30-50ms (CPU)
- **MAE (시선 각도): 평균 8.5-12°
- **우점:**
  - 경량성과 정확도의 좋은 균형
  - 모바일 배포 가능 (양자화 후 5-8ms)
- **단점:** 최고 정확도 아님

#### MobileNetV3
- **아키텍처:** 경량화 기법 (depthwise separable conv, SE block)
- **변형:**
  - MobileNetV3-Small: 2.5M 매개변수
  - MobileNetV3-Large: 5.4M 매개변수
- **성능 (Large):**
  - ImageNet Top-1: 75.2%
  - 지연시간: 3-8ms (GPU), 15-30ms (CPU)
- **MAE (시선): 평균 7.5-10°
- **우점:**
  - 극도로 빠른 추론
  - INT8 양자화로 스마트폰 배포 가능 (1-3ms)
  - SE block으로 채널 주의력 학습
- **단점:** 깊은 특징 추출 제한

#### EfficientNet-B0
- **아키텍처:** 복합 스케일링 (깊이, 너비, 해상도)
- **성능:**
  - 매개변수: 5.3M
  - ImageNet Top-1: 77.1%
  - 지연시간: 10-20ms (GPU), 40-80ms (CPU)
- **MAE (시선): 평균 6.5-8.5°** (최고 정확도
- **우점:**
  - ResNet-50 대비 26M → 5.3M (1/5 축소) 정확도는 높음
  - 스케일링 방법론 체계적
  - 정확도-효율성 파레토 최적
- **단점:**
  - MobileNetV3보다 느림
  - 차량 내장형 SoC 추론은 제약

### 5.2 DMS용 권장 아키텍처

```
성능 비교:

## 6. RGB에서 IR 도메인 적응

### 6.1 핵심 문제: RGB-IR 도메인 갭

#### 특성 차이

| 특성 | RGB | 적외선 (IR) |
|------|-----|----------|
| **파장** | 380-700nm (가시광) | 700nm-1mm (열복사) |
| **조명 의존성** | 높음 (야간 실패) | 낮음 (신체 온도로만) |
| **해상도** | 보통 1920×1080 | 저해상도 (320×256) |
| **대비** | 높음 | 낮음 (온도 차이 작음) |
| **깊이 정보** | 부분 (stereopsis) | 거의 없음 |

#### 실제 영향
```
ImageNet 사전학습 ResNet-50 성능:
  RGB 이미지: 정확도 76%

  같은 모델을 IR 이미지에 직접 적용:
  → 정확도 35-40% (급락!)

  원인:
  1) 이미지 통계 차이 (저해상도, 저대비)
  2) 특징 분포 불일치
  3) 카메라 특성 차이 (센서 노이즈)
```

### 6.2 2024-2025 최신 적응 기법

#### 1) Progressive Domain Adaptation (2024-2025)

**적용 대상:** Thermal Infrared Tracking (PDAT 프레임워크)

**구조:**
```
Step 1: 적대적 글로벌 도메인 적응 (Adversarial Global DA)
  - 도메인 판별자 D: "이 특징은 RGB인가 IR인가?"
  - 생성기 G: D를 속이도록 특징 변환
  - 손실: L_adv = -E[log D(G(f_IR))] + E[log D(f_RGB)]

  효과: RGB-IR 특징 분포 대략적 정렬

Step 2: 클러스터링 기반 소도메인 적응 (Clustering-based Subdomain DA)
  - 각 도메인의 특징을 k개 클러스터로 분할
  - 같은 클래스 내 클러스터끼리만 정렬 (세밀한 적응)
  - 이종 객체(예: 차 vs 사람)의 특징 혼동 방지

결과: NTU RGB+D 추적 벤치마크에서 ~6% 성공률 향상
```

**DMS 적용:**
```
RGB 사전학습 모델 (얼굴 검출, 시선 추정)
  ↓
Step 1: IR 카메라로 대규모 미레이블 데이터 수집
  (약 10,000 장, 다양한 조명 조건)
  ↓
Step 2: 적대적 도메인 적응 학습
  - 도메인 판별자 추가
  - RGB 데이터셋 (COCO, VGGFace) + IR 미레이블 데이터
  - 20-30 에포크 학습
  ↓
Step 3: 소도메인 세분화
  - 얼굴/손 영역별로 클러스터링
  - 선글라스/마스크 등 오클루전 클래스별 적응
  ↓
결과: IR 이미지에서 정확도 55-60% → 75-80% 향상
```

#### 2) Lightweight Infrared Image Denoising (2024)

**방법:** 전이 학습 기반 2단계 학습

**Step 1: 가시광선 큰 데이터셋에서 사전학습**
```
생성기 G 학습:
  - 입력: 가우시안 노이즈 추가한 정상 이미지
  - 출력: 복원 이미지
  - 손실: L_recon = ||G(noisy) - clean||_2²
           + L_adv = -log D(G(noisy))
           + L_perceptual = ||f_VGG(G(noisy)) - f_VGG(clean)||_2²

  데이터: DIV2K (가시광선 1,800장)
  결과: 초기 감지 능력 학습
```

**Step 2: IR 데이터셋에서 미세조정**
```
동결된 계층: 초기 수 계층 (저수준 특징)
미세조정: 중간-깊은 계층 (도메인 특화 특징)

손실: 동일한 구조 유지, IR 데이터에 맞춤
      L_ir = L_recon + λ_adv × L_adv + λ_perc × L_perceptual

λ_adv, λ_perc: 가중 팩터 (0.1-0.5 범위)

결과:
  - IR 이미지 PSNR: 28dB → 35dB (잡음 감소)
  - 이후 얼굴 검출 정확도: 55% → 78%
```

#### 3) CNN 기반 Thermal Person Detection (도메인 적응)

**아키텍처:**
```
RGB 사전학습 Faster R-CNN 또는 YOLOv8
  ↓
Feature Pyramid 수정:
  - RGB 채널 (3) → Grayscale 변환 후 3배 복제 (온도 그래디언트 정보 보존)
  또는
  - 새로운 입력 정규화 (IR 특화)
  ↓
도메인 적응 손실:
  - Classification loss: standard
  - Domain discrimination loss: RGB vs IR 특징 판별
  ↓
Fine-tuning:
  - 학습률: 10배 감소 (2e-5 → 2e-4)
  - 배치 크기: RGB + IR 혼합 배치
  - 에포크: 50-100 (RGB 기반 150 에포크보다 적음)

결과:
  - RGB 데이터: AP 45% (유지)
  - IR 데이터: AP 28% → 38% (+35% 향상)
```

│                                        │

│   1) 정상 얼굴 (조명 양호)             │
│   2) 저조도 얼굴 (밝기 낮음)           │
│   3) 부분 가림 (선글라스)              │
│   4) 부분 가림 (마스크)                │
│   5) 심각 가림 (여러 겹)               │
│                                        │
│ 클러스터별 분류자:                    │
│   y_{i,c} = head_c(f_i) for c ∈ {1..5}│
│                                        │
│ 손실:                                  │
│   L_cluster = Σ_c ||y_{i,c} - y_{j,c}║ │
│             (같은 클러스터 내 일관성)   │
│                                        │
│ 에포크: 20                             │
│ 결과: IR 정확도 78% → 82%              │
└────────────────────────────────────────┘
           ↓
       최종 DMS 모델 준비 완료
```

## 7. DMS 실패 사례 처리

### 7.1 전형적 실패 시나리오

#### 시나리오 A: 얼굴 검출 실패 (극저조도)

**상황:**
- 터널 돌입, 조도 < 5 lux
- RGB 카메라로는 픽셀 거의 검은색
- IR 카메라는 정상 작동 (신체 온도 기준)

**Fallback 전략:**
```
Step 1: 얼굴 검출 시도
  ↓ (실패, bbox 신뢰도 < 0.3)

Step 2: Degraded Mode 활성화
  - 신뢰도 표시: "LOW CONFIDENCE (0.15)"
  - IR 기반 머리 영역 추정으로 전환
  - 스켈레톤 포즈만 사용 → 행동 분류 (단순화)

Step 3: 조치
  - 졸음: 유지 (머리 고정 가능성)
  - 휴대폰: 감지 불가 (손 영역 불명확)
  - 사이드미러: 머리 회전 각도로 추정

Step 4: 사용자 피드백
  Display: "Camera in low-light mode (80% accuracy)"
           + 경고 기준 상향 (신뢰도 요구 90% → 70%)
```

#### 시나리오 B: 부분 가림 (선글라스 + 마스크)

**상황:**
- 운전자 선글라스 + 마스크 착용 (감염 우려 또는 개인 선호)
- 얼굴 40% 이상 가려짐
- 시선 추정 불가능

**Fallback:**
```
Branch별 신뢰도:
  - Gaze: 0.05 (거의 무용지물)
  - Pose: 0.78 (코, 턱 보임)
  - Occlusion: 0.95 (선글라스+마스크 정확히 감지)

가중치:
  w_gaze ≈ 0, w_pose ≈ 0.82, w_occlusion ≈ 0.18

동작:
  1) 포즈 중심 분류 (머리 회전 각도)
  2) 선글라스+마스크 정보로 "시선 신뢰도 매우 낮음" 표시
  3) 휴대폰 사용 감지 불가 (손 영역 안 보임)
     → 위험 행동 판정 기준 보수적 적용
     (휴대폰 사용 의심되어도 확신도 80% 이상 필요)

경고:
  - 졸음: 여전히 감지 가능 (머리 고개 숙임)
  - 전방 주시: 머리 회전 0° 근처로 판정
  - 불확실: 네비 vs 미러 vs 집중 (구분 불가)
    → 경고 기준 높임
```

#### 시나리오 C: 카메라 탁도/오염

**상황:**
- 카메라 렌즈 작은 이물질 부착
- 모든 특징점 신뢰도 10-20% 감소

**감지 메커니즘:**
```
신뢰도 모니터링:
  - 정상 프레임 평균 신뢰도: 0.75
  - 오염 상황: 0.35 (지속적 저하)
  - 임계값: 0.50 이하 5초 이상 지속

경고: "Camera quality degraded - Service required"
      + 시스템 모드 전환

복구 불가 상황: 안전 모드 진입 (경고만 강조)
```

### 7.2 Degraded Mode 동작 원리

```
┌─────────────────────────────────────────┐
│ Normal Mode (신뢰도 > 0.6)              │
├─────────────────────────────────────────┤
│ - 모든 branch 활용                      │
│ - 정밀한 행동 분류 (6-7개 클래스)      │
│ - 신뢰도 기준: 정상 (70-80%)            │
│ - 경고 임계값: 높음 (위험도 80% 이상)  │
└─────────────────────────────────────────┘
           ↓ (신뢰도 감소)

┌─────────────────────────────────────────┐
│ Degraded Mode Level 1 (신뢰도 0.3-0.6) │
├─────────────────────────────────────────┤
│ - 신뢰도 낮은 branch 제외                │
│ - 행동 클래스 단순화 (3-4개: 졸음/주의산만/정상) │
│ - 신뢰도 표시: LOW (50-60%)              │
│ - 경고 임계값: 상향 (위험도 60% 이상)   │
│ - 출력: "Low confidence mode active"    │
└─────────────────────────────────────────┘
           ↓ (신뢰도 추가 감소)

┌─────────────────────────────────────────┐
│ Degraded Mode Level 2 (신뢰도 < 0.3)   │
├─────────────────────────────────────────┤
│ - 하나 branch만 사용 (포즈)              │
│ - 극도로 단순화 (2개: 위험/안전)        │
│ - 신뢰도 표시: CRITICAL                 │
│ - 경고 임계값: 최소 (위험도 40%)        │
│ - 출력: "System degraded. Manual attention required" │
│ - 주기: 1초마다 경고음                  │
└─────────────────────────────────────────┘
           ↓ (완전 실패)

┌─────────────────────────────────────────┐
│ Failure Mode (신뢰도 = 0)               │
├─────────────────────────────────────────┤
│ - 차량 계기판 LED: 빨강 점멸            │
│ - 음성: "Camera failure detected"       │
│ - 데이터 수집: 중단 (가짜 판정 방지)   │
│ - 서비스: 필요 안내                     │
└─────────────────────────────────────────┘
```

### 7.3 실제 실패 처리 사례 (논문 기반)

#### 연구 사례 1: Face Detection Robustness (2024)

**환경:** 다양한 저조도, 진동, 렌즈 오염 조건

**결과:**
- **CNN (Faster R-CNN):** 정확도 저하 심각 (92% → 45%)
- **Capsule Network:** 정확도 저하 완만 (92% → 72%) **← 우수**

**메커니즘:**
```
CNN: 주로 저수준 특징(에지, 코너) 의존
  → 조도 변화에 민감
  → 선형 필터로 노이즈 추출 (오검출 증가)

Capsule Net: 부분-전체 계층 구조
  → 낮은 품질 입력 → 벡터 크기 감소 (신뢰도 자동 표현)
  → 노이즈에 덜 민감
```

**DMS 적용:**
- Capsule Network 기반 얼굴 검출 사용
- 출력: bbox + 신뢰도 벡터 (크기 그 자체가 신뢰도)

#### 연구 사례 2: Autonomous Vehicle Sensor Failure (2024)

**프레임워크:** Fallback 계층 구조

```
Level 1: 모든 센서 정상
  - 모든 정보 사용 (카메라 + 레이더 + LiDAR)
  - 최고 정밀도

Level 2: 한 센서 실패 (예: 카메라)
  - 나머지 센서 조합 (레이더 + LiDAR)
  - 감소된 정밀도로 주행 유지
  - 데이터 신뢰도 표시

Level 3: 다중 센서 실패
  - 관성 주행 (IMU + 속도 정보)
  - 속도 감소, 경고 활성화

Level 4: 완전 실패
  - 안전 정지 (차량 멈춤)

DMS 적용:
  Level 1: 모든 branch (시선+포즈+차폐) → 정밀 분류
  Level 2: 포즈만 사용 → 단순화 분류
  Level 3: 스켈레톤 기본만 → 기울기 탐지만
  Level 4: 시스템 정지 (경고 발송)
```

### 7.4 결론: Adaptive Confidence System

```
핵심 철학:
  "완벽한 정확도는 불가능.
   대신 현재 신뢰도를 명확히 하고
   그에 맞는 동작을 수행하자."

구현:
  1) 모든 추정값에 신뢰도 점수 동반
  2) 신뢰도에 따른 동작 모드 변경
  3) 사용자에게 투명하게 신뢰도 공개
  4) 낮은 신뢰도 상황에서 보수적 판정
  5) 완전 실패 시 안전 정지
```
